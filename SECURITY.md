# Безпека

## Чому це важливо

Плагін Claude Code виконується з правами користувача: хуки запускають команди на кожен виклик інструменту,
MCP-сервери — окремі процеси. Ізоляції від системи нема, і сторонні маркетплейси ніхто, крім їхніх авторів, не
перевіряє. Тому кожна зміна в `plugins/` проходить рев'ю власника з `.github/CODEOWNERS`.

## Підтримувані версії

| Плагін | Версія | Виправлення безпеки |
|---|---|---|
| `my-toolkit` | 1.x | так |
| `my-toolkit` | < 1.0 | ні |

## Як повідомити про вразливість

1. **Не** відкривати публічний issue.
2. GitHub → вкладка **Security** цього репо → **Report a vulnerability** (приватний звіт), або лист на
   1990vetalb1990@gmail.com з темою `[security] vetaloffline-team-marketplace`.
3. У звіті: плагін і версія, кроки відтворення, що саме можна зробити (виконати команду, прочитати файл,
   обійти заборону хука), версія Claude Code (`claude --version`).

## Що буде далі

| Крок | Строк |
|---|---|
| Підтвердження, що звіт отримано | 3 дні |
| Оцінка: вразливість чи ні, наскільки серйозна | 7 днів |
| Виправлення і реліз (patch або minor) для критичних | 14 днів |
| Публічний опис у GitHub Security Advisory і `CHANGELOG.md` | після релізу |

Строки — намір одного супровідника, не договір.

## Що вважається вразливістю

- Хук або skill виконує команду, яку користувач не просив і не бачить.
- Плагін передає файли, змінні середовища чи токени в мережу.
- Обхід заборони `guard-main.py` (наприклад, коміт у `main` проходить). Хук прямо не є межею безпеки — скрипти,
  alias і бектики він не розбирає, — але про обхід звичайною командою git теж варто повідомити.

## Чекліст рев'ю для PR у `plugins/`

- Хуки: на що matcher (не `.*` без причини), що запускає, чи ходить у мережу.
- MCP-сервери: звідки береться код, які змінні середовища отримує.
- Виконувані файли і скрипти: чи всі в репо, нема завантажень під час роботи.
- Змінні середовища: не читає секрети, які йому не потрібні.
- Мережеві виклики: куди і навіщо.
- Залежності: версії зафіксовані, нема відомих CVE.
