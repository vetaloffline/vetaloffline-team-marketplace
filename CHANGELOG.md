## sdlc

### [0.0.5] — 2026-10-28

#### Added

- Агент `sdlc:pr-fixer` (`agents/pr-fixer.md`, sonnet): веде цикл по чеках одного PR — чекає пайплайн,
  читає всі чеки, для червоного читає лог, фіксить на фіч-гілці, проганяє локальний гейт, комітить,
  пушить і перечитує все, поки червоних не лишиться. Не повертається, поки є чек у процесі: команду
  очікування перезапускає після таймауту; пайплайн без жодного джоба 30+ хвилин — питання (раннер).
  Питати користувача агент не може (`AskUserQuestion` агентам недоступний), тому на неясному випадку
  повертає `PRFIX_NEEDS_USER` з рядком логу, причиною й варіантами. Результат — `PRFIX_GREEN` /
  `PRFIX_NEEDS_USER` / `PRFIX_STOPPED` і таблиця чеків.

#### Changed

- `check-pr` став диспетчером: знаходить PR, визначає фордж, визначає локальний гейт і запускає по агенту
  `sdlc:pr-fixer` на кожен PR (паралельно для різних репо). На `PRFIX_NEEDS_USER` сесія питає користувача
  й продовжує того ж агента через `SendMessage` (`DECISION: …`). Поки агенти працюють, сесія хід не
  закінчує. Агент недоступний — general-purpose з текстом `pr-fixer.md`.
- `check-pr` визначає фордж за хостом: GitHub — `github.com` або хост, де `gh auth status --hostname` дає 0
  (GitHub Enterprise); GitLab — `gitlab.com` або хост, де це дає `glab` (self-hosted). Інший чи невідомий
  фордж (Bitbucket, Gitea/Forgejo, Azure DevOps…) — команд з пам'яті нема: скіл питає — ти читаєш чеки,
  а він фіксить; або ти називаєш CLI/API, і він спершу читає його `--help`; або чеки пропускаються з
  записом у звіті.
- `ship-feature` крок 5 визначає фордж так само. Раніше будь-який не-GitHub remote вважався GitLab, і для
  Bitbucket пропонувався `glab`. Тепер для іншого форджа — гілка й тіло PR для ручного створення і питання
  про посилання на PR. Крок 6 описує запуск агента й питання від нього.
- `agent-roster.md` і README: 12 агентів, `pr-fixer` у таблицях.

### [0.0.4] — 2026-10-28

#### Added

- Новий скіл `check-pr` (`/sdlc:check-pr <url>`, «перевір PR», «перевір чеки»): після створення PR/MR читає
  всі чеки його пайплайна, для кожного червоного читає лог, шукає причину, фіксить на фіч-гілці, проганяє
  локальний гейт, комітить, пушить і перечитує всі чеки — і так поки червоних не лишиться. Manual /
  `allow_failure` / skipped джоби — не падіння, вони йдуть у звіт. Вкладені код-репо — цикл на кожен PR.
  Команди `gh` / `glab` звірені з `--help` і на живих PR/MR. Зупиняється й питає через `AskUserQuestion`,
  коли причина в іншому репо або в порядку мерджу/деплою (e2e app клонує `main` api без фічі), flaky чи
  падіння раннера, фікс міняє PRD/AC/контракт, фікс послаблює тест, потрібні секрети чи налаштування CI,
  чек скасовано, той самий чек червоний після 3 спроб.
- `ship-feature`, новий крок 6: запускає `check-pr` на кожен PR, який створив.
- PostToolUse-хук `hooks/pr-created.py`: після будь-якого `gh pr create` / `glab mr create` у сесії додає
  Claude нотатку з URL PR і `/sdlc:check-pr <url>` — так перевіряється й PR, створений поза `ship-feature`.
  Тести: `bash plugins/sdlc/hooks/test-pr-created.sh`.

#### Changed

- `ship-feature` створює PR лише після «так» користувача; у PR body з'явився рядок «Merge order» для PR, які
  залежать один від одного. Ніколи не мерджить і не вмикає auto-merge, тест не послаблює і джоб не вимикає.
  Звіт по чеках — у handoff (*What I did*), кінцевий стан: усе зелене / чекаю на рішення / зупинився.

### [0.0.3] — 2026-10-28

#### Added

- `implement-tasks`, новий крок 10: якщо прогін зачепив UI (є задача `layer: ui` або змінено файли
  UI-поверхні з `target_surfaces`), скіл питає користувача — перевірити в браузері через `verify-ui` чи
  одразу йти на ревʼю. Вирішує людина. Для чисто бекендового прогону питання не ставиться. Вибір
  фіксується в `docs/features/<slug>/_review/verify-ui.md` (вердикти або рядок «skipped by the user»).
  FAIL у браузері повертає задачу в TDD-цикл; без браузерних інструментів — стоп і чекати.

#### Changed

- `verify-ui` перевіряє всі AC і всі UI-флоу з `sad.md` §6, включно з порожніми, помилковими та
  крайовими станами, на десктопі й на мобільному viewport (375×812, якщо правила проєкту не задають
  інший), зі скріншотом на кожен AC і viewport. Нова передумова: якщо браузерних інструментів сесії
  немає або вони не підключаються — стоп і чекати, без вердикту з тестів. Будь-який браузерний
  інструмент сесії підходить, не лише `playwright-cli`.
- `review-feature` читає `_review/verify-ui.md`: вердикти — доказ для UI-AC; FAIL — блокуюча знахідка;
  «skipped by the user» — записується в звіт, але не знахідка; файлу нема при зміненому UI — знахідка.

### [0.0.2] — 2026-10-27

#### Changed

- `complete-sequence-diagrams` питає не «які флоу мають бути», а чи правильно згенеровані флоу: інвентар
  (крок 2), кожна діаграма (крок 6) і N/A-рядки покриття (крок 7) подаються як рев'ю з рядком «Джерела: …»
  (US/AC, розділ `sad` чи ADR, `file:line` у коді). Опції — «Все вірно, апрув» / «Є розбіжність з джерелом —
  виправити» / «Відкласти в OQ» / «Прибрати». Owner: Tech Lead перевіряє технічну правильність, PM на цій
  стадії нічого нового не вирішує.
- Нове правило джерел: поведінку, якої нема в PRD, SAD чи коді, скіл не домальовує і не просить вигадати —
  позначає `source gap` у блоці, пише у `**Flags:**` і в handoff відправляє в `/sdlc:clarify-prd` (продукт)
  чи `/sdlc:architecture-design` (техніка).
- `_shared/diagram-presentation.md`: питання-підтвердження діаграми — опис прозою + рядок «Джерела: …»,
  сформульоване як рев'ю. `_shared/ask-style.md`: нова секція «Review of a derived artifact» з канонічним
  набором опцій рев'ю.
- Мова питань: замість «Ukrainian throughout» `AskUserQuestion` ставиться мовою, якою говорить користувач
  (мова відповідей сесії, інакше мова його повідомлень). Скіли й приклади описані англійською, Claude
  перекладає їх під час питання. Правило в `_shared/ask-style.md` → *Language*; `interview`, `write-prd` і
  `architecture-design` посилаються на нього. `ask-style.md` повністю англійською.
- Весь текст плагіна `plugins/sdlc` — англійською: TL;DR-вступи, описи скілів, приклади питань, шаблони SAD/ADR,
  `README.md`, `plugin.json`, тести й фікстури. Українськими лишилися тільки тригер-фрази у frontmatter скілів
  (`"діаграми послідовності {slug}"` тощо) — за ними скіл спрацьовує, коли користувач пише українською.

## my-toolkit

### [1.1.0] — 2026-10-26

#### Added

- PreToolUse-хук `guard-rm.py` на `rm`, `unlink`, `find -delete` і `find -exec rm`, також за `sudo`, `bash -c`,
  `cd …&&` і heredoc: шляхи строго в `/tmp` і `$TMPDIR` поза проєктом — без питань; деінде або коли шлях не
  видно до запуску — `ask`; рекурсивно `/`, `~`, корінь проєкту чи вище, вкладене git-репо, сама тимчасова чи
  вільна папка, шаблон у корені проєкту — заборона.
- `.claude/guard-rm.json` проєкту: `{"safe_dirs": [...]}` — папки проєкту, де видалення йде без питань
  (як `art/drafts` у dronehold).
- `test-guard-rm.sh`: 108 перевірок; `/my-toolkit:guard-test` проганяє обидва тести.

#### Changed

- Плагін увімкнений глобально або в проєкті тепер питає дозволу на будь-яке видалення поза тимчасовими й
  вільними папками. Проєкт, якому потрібна своя папка без питань, оголошує її в `.claude/guard-rm.json`.
